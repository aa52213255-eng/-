# 병맛 장애물 달리기 (가제) 설계

작성일: 2026-11-11 · 형태: 웹 게임 (HTML 파일 1개) · 파일명: `byeongmat-obby.html`

## 1. 목표와 성공 기준

크리스탈 러시 같은 "숫자만 커지는 클릭 게임"이 지겨워서, **직접 조작하고, 죽으면 웃기고, "한 번만 더!" 하게 되는** 2D 장애물 달리기를 만든다.

성공 기준:
- 처음 켠 사람이 설명 없이 10초 안에 조작을 이해한다.
- 죽고 다시 시작하기까지 1초가 안 걸린다 (지겨워지지 않게).
- 스테이지 8개를 모두 클리어할 수 있다 (자동 검사로 보장, 6장 참고).
- 폰(세로·가로)과 컴퓨터에서 모두 플레이된다.

## 2. 범위

포함: 스테이지 8개, 보스 2명, 병맛 장애물 약 12종, 웃긴 사망 문구, 업적, 저장, 효과음, 터치 조작.

제외: 멀티플레이, 3D, 서버, 긴 스토리 컷씬, 외부 이미지·음원 파일(그림은 이모지와 도형, 소리는 WebAudio로 만든다).

가정: 2D 옆으로 달리는 방식이다. 이모지는 기기마다 모양이 조금 달라 보일 수 있고, 이건 허용한다.

## 3. 조작과 물리

- 화면은 논리 해상도 960×540, 창 크기에 맞춰 비율을 유지하며 확대한다. 타일 크기는 32px.
- 컴퓨터: ← → (또는 A D) 이동, Space·↑·W 점프, Esc 일시정지.
- 폰: 왼쪽 아래 ◀ ▶ 버튼, 오른쪽 아래 점프 버튼. 멀티터치(이동하면서 점프) 지원.
- 고정 시간 간격 60Hz로 계산해서 기기 성능과 상관없이 같은 느낌이다.
- 기본값(손맛 조정 가능하도록 상수로 분리):
  - 최고 속도 260px/s, 가속·감속 있음
  - 중력 2000px/s², 점프 초속 640px/s (높이 약 3타일)
  - **점프 길게 누르기:** 버튼을 일찍 떼면 상승 속도가 절반이 되어 낮게 뛴다
  - **코요테 타임 0.1초:** 발판을 벗어난 직후에도 점프 가능
  - **점프 예약 0.12초:** 착지 직전에 누른 점프가 착지하면 나간다
- 이중 점프는 없다.

## 4. 스테이지

각 스테이지는 데이터(문자열 타일맵 + 오브젝트 목록)로 정의한다. 길이는 3~5화면, 숙련자 기준 1~2분, 체크포인트 2개, 끝에 골 깃발.

| # | 이름 | 병맛 장애물 |
|---|---|---|
| 1 | 🍗 치킨 공장 | 날아오는 치킨(포물선), 쾅 내리치는 닭다리 프레스 |
| 2 | 🍌 바나나 빙판 | 마찰이 낮은 바나나 바닥, 굴러오는 바나나 껍질 |
| 3 | 🏫 지각 학교 | 날아오는 지우개, 혼자 움직이는 사물함(움직이는 발판) |
| 4 | 👑 보스: 거대 감자튀김 | 7장 참고 |
| 5 | 🍜 라면 온천 | 끓는 국물(닿으면 사망), 흔들리는 면발 그네(진자) |
| 6 | 🛒 우주 편의점 | 무중력 구간, 도망가는 삼각김밥(밟고 가는 발판) |
| 7 | 📶 와이파이 끊긴 마을 | 로딩 중이라 깜빡이며 사라지는 바닥 |
| 8 | 🌀 최종 보스: 말하는 포탈 | 7장 참고 |

장애물 종류는 공통 부품으로 만들어 스테이지끼리 재사용한다. 부품마다 `update(dt)`, `draw()`, `hits(player)` 세 가지만 가진다.

난이도는 1→8로 갈수록 올라가고, 1~2는 처음 해 보는 사람도 한 번에 깰 수 있을 정도로 쉽게 한다.

## 5. 병맛 요소

- **사망 문구:** 죽을 때마다 화면 중앙에 랜덤으로 뜬다. 장애물별 전용 문구(예: 치킨에 맞으면 "치킨이 더 빨랐습니다")와 공통 문구(예: "감자는 오늘도 구워졌습니다") 합쳐 **30개 이상**.
- **빠른 부활:** 사망 연출 0.4초 후 마지막 체크포인트에서 바로 부활한다.
- **죽은 횟수 표시:** 화면 구석에 "🥔💀 × N"을 보여 준다.
- **스테이지 이름 카드:** 시작할 때 웃긴 부제와 함께 보여 준다.
- **업적(6개):** 첫 죽음, 10번·50번·100번·300번 죽음("인내의 감자"), 노데스 클리어 1개.
- **엔딩:** 최종 보스 격파 후 병맛 엔딩 문구, 총 죽은 횟수 표시.

## 6. 자동 검사로 "깰 수 있음"을 보장하기

물리 상수로 **최대 점프 거리와 높이를 계산하는 함수**를 두고, 테스트에서 모든 스테이지의 발판 사이 간격·높이 차가 이 범위 안(여유 10% 포함)인지 검사한다. 움직이는 발판·깜빡이는 바닥은 "움직이는 동안 도달 가능한 시간 창이 있는지"를 검사한다. 이 검사가 통과해야 스테이지가 완성이다.

## 7. 보스

보스는 공격하지 않고, **피하다가 약점 스위치를 누르는 방식**이다.

- **거대 감자튀김(스테이지 4):** 아레나 하나. 위에서 감자튀김 막대가 3줄씩 떨어지고, 떨어지기 0.6초 전에 바닥에 그림자로 예고한다. 소스 웅덩이가 바닥 일부를 막는다. 아레나 양 끝에 번갈아 나타나는 스위치를 **3번** 누르면 클리어.
- **말하는 포탈(스테이지 8):** 헛소리 말풍선을 계속 띄우며, 이전 스테이지 장애물(치킨·지우개·바나나 껍질)을 섞어 던진다. 스위치를 **5번** 누르면 클리어. 3번째부터 패턴이 빨라진다.
- 보스전 중 죽으면 보스전 시작 지점에서 부활하고, 스위치 진행도는 초기화된다.

## 8. 화면 흐름

타이틀 → 스테이지 선택(잠금·최고 기록 표시) → 플레이 → 클리어 화면(시간·죽은 횟수) → 스테이지 선택. 플레이 중 Esc로 일시정지(계속하기 / 스테이지 선택 / 소리 켜고 끄기).

## 9. 저장

- 브라우저 `localStorage` 한 칸(`byeongmat-obby-v1`)에 JSON으로 저장: 해금된 스테이지, 스테이지별 최고 시간·최소 죽은 횟수, 총 죽은 횟수, 업적, 소리 설정.
- 저장 읽기·쓰기는 모두 `try/catch`로 감싸고, 저장이 막혀 있어도 게임은 정상 동작한다 (기록만 안 남는다는 안내 표시).
- 저장 데이터가 깨져 있으면 새로 시작하고, 깨진 데이터는 덮어쓰기 전에 다른 칸에 백업한다.

## 10. 소리

WebAudio로 만든 효과음: 점프, 착지, 사망("뿅"), 체크포인트, 클리어, 보스 스위치. 기본은 꺼짐이고 일시정지 화면과 타이틀에서 켠다. 첫 터치 이후에만 재생한다 (브라우저 규칙).

## 11. 코드 구조 (파일 1개 안의 구역)

외부 라이브러리 없이 순수 JavaScript + Canvas 2D로 만든다.

| 구역 | 책임 |
|---|---|
| Input | 키보드·터치를 "왼쪽/오른쪽/점프" 상태로 통일 |
| Physics | 이동·점프·충돌·최대 점프 거리 계산 (화면과 상관없는 순수 함수) |
| Level | 스테이지 데이터 읽기, 체크포인트 관리 |
| Entities | 장애물 부품들 |
| Bosses | 두 보스의 패턴 |
| UI | 타이틀·선택·HUD·일시정지·클리어·엔딩 |
| Save | 저장·불러오기·업적 |
| Audio | 효과음 |

Physics와 Level 검사는 Node.js에서도 불러올 수 있게 DOM에 의존하지 않는다.

## 12. 테스트 계획

1. **Node 테스트:** 점프 거리 계산, 충돌 판정, 저장 데이터 검증, 사망 문구 개수, **8개 스테이지 도달 가능성 검사**.
2. **브라우저(Playwright) 스모크:** 오류 없이 켜지는지, 8개 스테이지가 모두 로드되는지, 키 입력으로 이동·점프·사망·부활이 되는지, 저장이 막힌 브라우저에서도 켜지는지.
3. **모바일 화면:** 세로·가로 크기에서 버튼 위치와 크기를 스크린샷으로 확인.
4. **직접 플레이 확인:** 완성 후 링크로 올려서 손맛과 난이도를 같이 조정한다.

## 13. 만드는 순서

1. 이동·점프·충돌 + 스테이지 1 하나만 먼저 (손맛 확인)
2. 사망·부활·체크포인트·사망 문구
3. 나머지 장애물 부품 + 스테이지 2~3, 5~7
4. 보스 2명 + 스테이지 4, 8
5. 타이틀·스테이지 선택·저장·업적·엔딩
6. 소리·모바일 버튼·다듬기
